# 智能城市生成系统 — 前端原型

> 团队作业的 **前端原型**：多角色登录 + 模板商城 + 管理员审核后台 + 分析师验收中心 + "进入 Blender 生成"模拟入口。
> 技术栈：React 19 + TypeScript + Vite。**纯静态前端，无后端依赖、无本地绝对路径**，`npm install` 即可在任意机器复现。

## 功能

- **多角色登录**：场景建模师 / 系统管理员 / 行业分析师，按角色显示不同权限页面（登录态存 `localStorage`）。
- **登录有效期**：登录态默认 12 小时后自动失效；页面保持打开时也会到点自动退出。
- **注册唯一性规则**：用户名全局唯一；邮箱允许分别注册不同角色，但同一邮箱不能拥有两个同角色账号。
- **模板商城**：展示 3 个整城模板（公园城市 / 金秋商业街 / 滨海社区），每个模板配 iCity 真实缩略图（树 / 路面 / 座椅）+ 整城场景概要（交通 / 人群 / 生态）。
- **模板详情**：参数一览 + "在 Blender 中应用此模板"模拟按钮（对应插件里的模板 0/1/2）。
- **管理员权限分配**：管理员可查看本地注册用户，通过下拉框分配用户角色，也可从本地用户库中完全删除用户；若改权会导致同邮箱同角色重复，系统会阻止并提示先删除重复用户。
- **管理员插件上架审核**：插件审核独立在 `/admin/audit` 页面；插件提交物需先经过行业分析师验收，通过后进入管理员审核队列，管理员可查看详情抽屉、填写审核意见并执行"通过上架 / 驳回"。
- **管理员操作日志**：记录角色变更、删除用户、插件上架、插件驳回等后台操作。
- **行业分析师标准与验收**：分析师可维护验收标准库，对插件提交物填写验收意见，执行"验收通过并提交管理员 / 要求修改"。
- **行业需求 Markdown 备忘录**：分析师可用 Markdown 记录智慧城市行业需求调研，并在右侧实时预览。

## 运行

```bash
cd frontend
npm install        # 首次：按 package-lock.json 锁定版本安装
npm run dev        # 本地开发（默认 http://localhost:5173）
npm run build      # 产物输出到 dist/
npm run preview    # 预览构建产物
```

> 需要 Node.js 18+。依赖版本已由 `package-lock.json` 锁定，保证不同机器装出一致的依赖树。

## 目录

| 路径 | 作用 |
| --- | --- |
| `src/templates.ts` | **模板数据源**：3 个整城模板（资产 + 场景概要 + 缩略图引用）、角色定义、`getTemplate()`。 |
| `src/App.tsx` | 主应用：登录、模板商城、模板详情、管理员后台、分析师验收中心、角色权限守卫。 |
| `src/assets/templates/` | iCity 真实缩略图（`road/tree/bench-0/1/2.png`，与插件 `templates.json` 的 3 个模板一一对应）。 |
| `public/` | 站点图标（`favicon.svg` / `icons.svg`）。 |

## 与插件的对应关系

前端模板商城的 3 个模板，与插件 `iCity/smart_city/manifests/templates.json` 中的模板 0/1/2 **数据一致**（树/路面/座椅资产、交通/人群/生态档位）。前端只做展示与"模拟应用"，真正的整城生成由 Blender 插件完成。

## 角色流程

| 角色 | 核心页面 | 能力 |
| --- | --- | --- |
| 场景建模师 | `/dashboard`、`/templates`、`/plugin-entry` | 选择模板、查看参数、模拟进入 Blender 插件。 |
| 行业分析师 | `/dashboard`、`/analyst` | 制定验收标准、记录行业需求、验收插件提交物并提交管理员审核。 |
| 系统管理员 | `/dashboard`、`/admin`、`/admin/audit` | 分配本地用户角色、删除用户、查看权限矩阵、处理分析师验收后的插件上架审核、查看操作日志。 |
