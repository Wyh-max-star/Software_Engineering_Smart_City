# ICity Pedestrians（行人模拟）

## 这个模块做了什么

`ICity Pedestrians` 是 `smart_city` 文件夹下新增的一个**独立扩展面板**，与已有的
`ICity Traffic & Crowd`（交通）和 `ICity Ecology`（河流 / 生态）并列，挂在原版
`iCity Start` 之上。

它的目标是：**用项目自带的真实角色动画，把城市填上符合社会常理的行人。**

与原交通模块里那种“低多边形小方块行人”不同，本模块直接导入并播放：

- `iCity/assets/Assets/Default/People/Walking.fbx` —— 行走循环动画，用于**移动的行人**；
- `iCity/assets/Assets/Default/People/Standing.fbx` —— 站立 / 待机动画，用于**停留的行人**。

新增 / 修改的文件：

| 文件 | 说明 |
| --- | --- |
| `smart_city/pedestrian_extension.py` | 行人模拟的全部逻辑、操作符与面板（新增） |
| `iCity/__init__.py` | 注册 / 注销新模块（修改：导入、`register`、`unregister`） |
| `smart_city/manifests/asset_manifest.json` | 登记两个 People FBX 资产，便于路径校验（修改） |
| `smart_city/docs/README_PEDESTRIAN.md` | 本说明文档（新增） |
| `tests/test_smart_city_pedestrians.py` | 纯逻辑单元测试（新增） |

## 怎么体现“社会常理”

行人不是随机乱走的，本模块刻意编码了几条日常生活中的规律：

1. **走在你指定的人行道带内，不走机动车道。**
   人行道由两个参数定义：**`Sidewalk Near`（距路中心线最近距离）** 和
   **`Sidewalk Far`（最远距离）**。模块复用交通模块的道路图（`Road del`），
   把每条道路中心线两侧、在 `[Near, Far]` 这条带内铺多条行走线，行人就在这条带里走。
   你直接按场景把这两个值调到人行道所在的距离即可（例如 `4`~`6`），所见即所得，
   不再依赖任何自动猜测。实现见 `plan_sidewalk_routes` / `band_distances`。

2. **两侧人行道方向相反（靠一侧通行）。**
   同一条街的左右两条人行道被生成为**方向相反**的两条路线，
   模拟现实中“各走各的一侧”的双向人流，而不是所有人挤在一条线上。

3. **面朝行进方向。**
   每个行人挂在一个沿路径运动的载体（carrier）上，载体每帧根据前进方向计算偏航角
   （`_keyframe_pedestrian_motion`），角色因此总是“脸朝着前进方向”走。

4. **匀速持续行走。**
   载体沿人行道**匀速持续行走**，全程不停顿（速度由 `Walk Speed` 控制，见下）。
   每个人的步速带随机扰动、相位错开，所以人流自然但不会忽走忽停。

5. **停留的人被强制站在人行道带正中，面朝街道。**
   站立行人**与行走行人共用同一条 `[Near, Far]` 人行道带**：取样点取自道路链的
   **段中点与内部转角顶点**，并**刻意避开链端点（即路口节点）**——因为在路口做垂直偏移
   很容易把人推到横向交叉的另一条路中央。取好点后被推到**人行道带正中**
   `(Near+Far)/2`，确保落点一定在 `[Near, Far]` 区间内。实现见
   `plan_idle_spots` / `_idle_candidate`。

6. **人群不整齐划一。**
   - 步速带随机扰动（`Speed Variation`），有人走得快有人走得慢；
   - 沿人行道有相位错开（phase），不会所有人挤成一团；
   - 站立行人的朝向带小幅随机偏转，不会齐刷刷正对同一方向。

7. **没有可读道路图时的兜底。**
   如果当前场景拿不到道路属性，模块会退回到城市外圈的椭圆环形人行道
   （`plan_fallback_loop_routes`），保证面板始终可用。

## 技术实现要点

- **只导入一次，复制多份。** 每个 FBX（约 35 MB）在一次生成中只被
  `bpy.ops.import_scene.fbx` 导入一次，作为隐藏的“模板”放进 `ICity Pedestrian Sources`。
  每个行人都是模板的轻量复制：共享网格 / 骨架数据与动画 Action，只复制对象本身，
  并把骨骼修改器（Armature modifier）重新指向复制出来的骨架。
- **路径平移 + 原地步循环（匀速）。** 角色的“走路姿态”由 FBX 自带 Action 提供（加 `CYCLES`
  循环修改器无限循环）；“沿街位移”由载体空物体的关键帧提供，**匀速持续行走、不停顿**。
  速度以**世界单位/帧**为单位由 `Walk Speed` 控制，并按路线长度归一化，
  所以不同长度的人行道上行人速度一致。
- **站立行人避开道路拐角，避免在城市圆角处踩空。** iCity 生成的城市四角是**圆弧**而非直角，
  在拐角处把站立点向外偏移会越过地面边缘、悬在**虚空**上。生成站立点前先用
  `corner_vertex_flags` 标出道路链上**发生转弯的顶点**（在一个小窗口内累计转角超过阈值即判为
  拐角，既能识别一次性的直角拐弯，也能识别由多段小转角拼出的圆弧），然后**跳过这些拐角顶点
  及其相邻路段**，只在道路的**直线段**上放置站立行人。该判定为纯函数、已被单元测试覆盖。
- **把角色水平居中到锚点，避免站立行人飘出窄带。** 自带动画并不总是把角色摆在骨架原点上，
  实例放到锚点时可能渲染到旁边半米左右；当人行道带很窄（如 `6.3`~`6.8`，仅 0.5 m）时，
  这点偏移就足以把**站立行人**挤出带外。导入时 `_center_template_horizontally` 会测出角色
  水平包围盒中心,把所有根对象（通过 Action 的位移通道或静态 location）反向平移这段偏移,
  让渲染出来的身体正好落在锚点上。安全起见,偏移过大（> 3 m）时跳过,避免把人甩飞。
- **剥离根位移（root motion），消除“走几十帧后瞬移回原点”。** 项目自带的 `Walking.fbx`
  里带有把整个身体往前平移的“根位移”；一旦动画加 `CYCLES` 循环，身体会在每个循环末尾
  **瞬间弹回**到动画起点——表现为“行人每隔几十帧就传送回原位”。由于沿街位移本应完全交给载体，
  导入时 `_strip_root_motion` 会扫描根骨骼 / 对象的位移曲线，把**单向漂移**（locomotion，
  净位移远大于摆动幅度）的通道压平，只保留像胯部上下颠这种**来回摆动**的通道，
  从而得到一个“原地迈步”的循环交给载体搬运，彻底消除瞬移。判别逻辑见纯函数
  `_drifts_monotonically`（已被单元测试覆盖）。
- **兼容新版 Action 数据结构。** Blender 4.4+ / 5.x 把旧的扁平 `Action.fcurves`
  改成了 `layers → strips → channelbags` 的“带槽位（slotted）”结构，导入的角色动画上
  可能已经没有 `fcurves` 属性。`ecology_common.iter_action_fcurves` 同时兼容新旧两种结构
  来取曲线、加循环修改器；并且**不**逐个实例重指派 Action（复制对象时已经连槽位一起继承），
  避免在新结构下出现槽位绑定丢失。
- **自动适配身高与朝向。**
  - 身高：导入后按包围盒高度自动换算缩放，统一到 `Person Height (m)`，
    自动兼容 FBX 是以厘米还是米为单位导出的；
  - 朝向：通过 `Facing Offset`（默认 `90°`）把角色正面对齐到“前进方向”。
    若你的角色模型默认朝向不同，调这个值即可，无需改代码。
- **生成的层级结构。**

  ```
  ICity
  └─ ICity Pedestrians
     ├─ ICity Pedestrian Sources   (隐藏的 FBX 模板)
     ├─ ICity Pedestrian Walkers   (移动行人 + 路径载体)
     ├─ ICity Pedestrian Idlers    (站立行人)
     └─ ICity Pedestrian Paths     (预留)
  ```

- **干净的清除。** `Clear` 只删除 `ICity Pedestrians` 这棵子树，并顺带回收
  复制产生的孤立骨架 / 网格 / Action 数据块，**不会**动到原城市、资产扩展、生态或交通结果。

## 在 Blender 里怎么用

1. 打开原版 `ICity` 面板，点 `Start` 生成基础城市。
2. （建议）先用 `ICity Traffic & Crowd` 生成道路，让道路图可被读取，行人会贴着真实道路走。
3. 在右侧 `N` 面板找到 `ICity Pedestrians`。
4. 设置参数：
   - `Walkers` / `Idlers`：移动与停留的行人数量；
   - `Sidewalk Near` / `Sidewalk Far`：**人行道带距路中心线的最近 / 最远距离**，
     行人都走在这条带里。若行人在车道上，把这两个值一起调大直到落到人行道上；
   - `Walk Speed`：行走速度（越小越慢，匀速持续行走）；
   - `Person Height (m)`：统一身高；`Facing Offset`：角色正面朝向修正（默认 90°）；
   - `Speed Variation` / `Seed`：人群随机性；
   - `Start Frame` / `End Frame`：动画区间。
5. 点 `Generate / Update`。
6. 按时间轴 `Play` 播放，即可看到行人匀速沿人行道行走、停留的人站在人行道带正中。

## 参数速查

| 参数 | 默认 | 含义 |
| --- | --- | --- |
| Walkers | 16 | 行走的行人数量 |
| Idlers | 8 | 站立的行人数量 |
| Sidewalk Near | 6.3 | 人行道带距路中心线的**最近**距离（米）；走在车道上就调大 |
| Sidewalk Far | 6.8 | 人行道带距路中心线的**最远**距离（米） |
| Walk Speed | 0.2 | 行走速度（世界单位/帧，越小越慢，匀速） |
| Speed Variation | 0.3 | 步速随机幅度 |
| Person Height (m) | 1.72 | 统一目标身高（米） |
| Facing Offset | 90° | 角色正面 → 前进方向的旋转修正 |
| Seed | 7 | 随机种子（可复现） |
| Start / End Frame | 1 / 250 | 动画帧区间 |

## 已知限制（演示导向）

- 行人沿预设人行道路线行走，**不做实时避障**（不会互相躲避或停在红灯前）。
- 步循环为“原地动画 + 路径平移”，移动速度与迈步速度未严格对齐，可能有轻微滑步，属正常折中。
- 行人**匀速持续行走**，不做走走停停（按需求已移除停顿逻辑）。
- 所有行走的人共享同一段循环动画，腿部动作大致同步；变化主要来自不同的位置、
  速度与朝向，而非各自不同的姿态相位。
- 站立行人被强制放在人行道带正中 `(Near+Far)/2`，且角色已水平居中到锚点；
  但人本身有宽度，**带宽小于人体宽度时**（如 0.5 m），身体两侧仍可能略微探出带外，属正常。
- 站立行人只放在道路**直线段**上、跳过拐角，因此**圆角附近不会有站立行人**——
  这是为避免在城市圆角处踩空的有意取舍。行走行人不受此限，仍沿完整路线行走。
- 行人带 / 站立点都基于交通模块的道路图（`Road del`）。若拿不到道路图，会退回到城市外圈
  的椭圆环形人行道兜底。
- 若 `Facing Offset` 与你替换的角色模型不匹配，角色可能侧身/倒退行走，调整该参数即可。
